## 一句话主线

**我的项目核心目标是「充分利用异构算力」：用 map/reduce 这类骨架算子组合程序员标记的纯函数，让程序的语义与偏好从 C/C++ 源码传到 IR，再在 IR 层把程序切分成可分配到不同异构算力上运行的形态，由调度器完成异构放置。这半年来，我把它从「单个 matmul 的验证性原型」重构成了「一套通用框架的原型」。**

## 第一部分：整体思想（新愿景，重点展开）

> 这是 0711 之后、和老师讨论后成形的新愿景。分三层讲，核心在第三层「调度」。

### 1. 核心目标：充分利用异构算力
- 不是"把某个算子送到 CPU 或 GPU"，而是"把一个程序切分成多块，同时跑在不同异构算力上，充分利用它们"。

### 2. 三层愿景（一页图即可）
1. **语义表达层（语言）**：annotation 承载程序员意图 → 纯函数 + 骨架算子
2. **编译管线层（编译）**：skeleton IR → linalg → 多目标 lower
3. **调度层（核心，规划中）**：程序切分 + 异构放置

### 3. 调度层（核心卖点，展开讲）
- **独立于现有 pipeline**：调度器是操作系统用户层的独立程序（与 clang 并列的 driver，LLVM 概念），运行时把异构程序分发到不同算力——不是 MLIR pass。
- **为什么可行**：纯函数的「无副作用」⇒ 切分是安全的；骨架算子的「可组合性」⇒ 程序可自然切分/重组为独立调度单元。
- **切分粒度**：动态可调、不固定——随异构设备加入/消失，动态求最优解。
- **调度时机**：静态切分 + 动态决策（编译期生成候选切分形态，运行时按实际设备状态选定）。
- **preference 是软约束**：调度器尽量"尊重"程序员意图；硬件不满足则改派其他设备，或回退 CPU。
- **异构范围**：当前聚焦 CPU + GPU（先把 GPU 搞定），未来扩展 NPU（待定）；跨机器是更远期工作。

### 4. 语义表达层：骨架编程模型（简述）
- 骨架算子（map/reduce）+ 纯函数（pure）+ region 嵌套 + preference。
- 两条前端路径（手动=原型、半自动=stub）最终产出统一 IR。

### 5. 编译管线层：pipeline（一页图，简述）
- C++ → skeleton IR → pattern-merge → to-linalg → preference-partition → target-lower → 可执行。
- 注意：调度层**独立于**这条 pipeline——它是独立的用户态调度器（与 clang 并列的 driver），在运行时把程序分发到不同算力。

## 第二部分：实现进展（0711 之后）

### 旧原型 vs 新原型（重点，先给对比）

| 维度 | 旧原型（0711 前，custom_matmul） | 新原型（0711 后，map/reduce） |
|------|----------------------------------|------------------------------|
| 定位 | 可行性验证：证明"preference → GPU"走得通 | 通用框架：骨架编程 + 完整编译链路 |
| op 集 | 单个 custom_matmul | 通用 map / reduce / vector_add / yield + region 嵌套 |
| pipeline | 为 matmul 定制（partition/target-lower 只认 matmul） | 5 个 pass 泛化（含 pattern-merge） |
| 前端 | 无（纯手写 MLIR） | 新增 CIR 前端（手动=原型、半自动=stub） |
| 完成度 | 链路能跑，但只覆盖一种模式 | MLIR 层完整且验证充分；前端反而退回原型 |

> 一句话：旧原型是"验证一个算子能不能多目标"，新原型是"搭一套通用框架"——格局和完成度都不同。

### 7 月的实质工作：重构出通用框架
- 把"只支持 matmul"换成通用 map/reduce（可组合、可嵌套）。
- 引入 pattern-merge：`map{pure_fn=@add}` → `vector_add`（named op）。
- MLIR 层端到端跑通：map-add、reduce-sum 的 CPU 集成 + matmul 的 CPU/GPU 集成全过。

### 8 月的实质工作：工程化与质量
- **构建工程化**（08-06）：统一 binaryDir、清理预设层级，让有/无 CUDA 的机器编辑体验一致。
- **技术债清理**（08-20）：把机器相关的 CMakeUserPresets 从 git 移出、纳入 .profile 模板托管，配置与代码分离。
- **质量工程**（08-21）：系统性 review 了这半年的变更，产出缺陷清单——最近正在 review 之前写的源码。

### 如实定位（一句带过，不展开）
- 能跑：MLIR 层全部（IR + 5 pass + CPU/GPU lowering）。
- 原型：全手动路径 CIR 前端（还没端到端跑通）。
- 下一步：把调度层从愿景落到实现（先做独立的用户态调度器 driver，聚焦 GPU）。

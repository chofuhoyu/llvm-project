# 组会汇报：三层架构上的位置

> 2026-09-19 → 2026-11-07。九月的主线是算子识别，已收在 `20261012.md`；十月中下旬方向收敛为
> 运行时放置，编译层随之只负责承载算子。下面按架构图的三层各取三条，标出各自的完成度。

## 一、编译层：C++ 整段程序进入 skeleton 管线

- **整程序前端**〔已落地〕：`main`、控制流、标准库调用与 `printf` 都经 ClangIR 进入 MLIR，
  C++ 不再只是描述算子的片段语言。
- **算子单元与边界**〔已落地〕：被标注的算子切成独立单元，一个算子对应一次放置决策；
  host 与单元在同一模块共存，边界按目的地传参。
- **第一个真实算子**〔进行中〕：softmax 拆成 reduce → map → reduce → map 的扁平 DAG，
  CPU 上一条命令跑出正确数值；GPU 只覆盖静态形状的逐元素单元，归约还没上设备。

## 二、调度层：放置决策从编译期移到运行时

- **注入重编译**〔已落地〕：产物只带 CPU 实现与内嵌 IR，GPU 实现由 driver 运行时按算子现编，
  编译期不再选定设备。
- **设备元信息**〔已落地〕：运行时探测设备可用性与空闲显存，preference 不可用或放不下时
  回退 CPU，没有可用实现时干净退出。
- **策略与粒度**〔进行中〕：决策粒度是单个算子，v1 策略是 preference 优先；
  负载均衡与 Tile/Fusion 还没做，扁平 DAG 每步都落内存。

## 三、用户界面：让三层可观测、可配置

- **构建入口**〔已落地〕：`skeleton++` 一条命令串起 clang / cir-opt / driver；
  构建与测试统一跑在远端 GPU 主机上。
- **调度决策日志**〔已落地〕：每次解析输出一行 `op / pref / probe / free / choose / reason`，
  可以直接当作实验数据。
- **监控与配置**〔未开始〕：设备与任务监控面板、调度策略配置仍是空白；
  下一步先用日志画出设备争用曲线。

## 演讲稿（约 500 字）

各位老师好，我用这张架构图汇报九月十九号以来的进展。三层里，编译层和调度层已经连成一条
能跑通的链路，用户界面刚起步。

先看左边编译层。最大的变化是 C++ 的角色变了：以前只能写算子，`main` 和打印都得手写 MLIR；
现在整段程序都能进来——`main`、控制流、标准库调用都经 ClangIR 进入 MLIR，被标注的算子切成
独立单元，其余部分照常降成机器码。第一个真实算子 softmax 已经用四个骨架算子组成扁平 DAG，
在 CPU 上一条命令跑出正确数值；GPU 目前只覆盖静态形状的逐元素单元，归约还上不去。

右边调度层的关键是图上这条「注入重编译」。产物里只放 CPU 实现和内嵌 IR，GPU 代码是运行时
按算子现编的。每次调用先查设备元信息——设备在不在、显存够不够——preference 满足就用，
否则回退 CPU，并留下一行决策日志。所以设备选择真的发生在运行时，不是编译期。

最上面用户界面这层，目前只有两块：一条命令的构建入口，和刚说的决策日志；监控面板、
策略配置还没开始。下一步先做设备争用曲线：让 GPU 从空闲到被占满，看系统能不能自动退回
CPU，把数据从日志里长出来，再谈面板和策略。谢谢。

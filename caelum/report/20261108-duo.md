# 运行时算子放置：第一阶段工作报告

> 范围：`caelum/skeleton-dialect`，2026-10-27 至 2026-11-03（`9b3df4a80a6d..78a854b8eab2`）。

## 一、工作进展

本阶段主要工作是把算子放置的决策点从编译期移到运行时。

1. 执行路径。数据搬运与计算之间缺少顺序约束，根据实验，这是偶发错误的来源；
现改为宿主与设备共享同一块内存，搬运与计算串行执行，去除异步等待。

2. 运行时架构。编译期只切分算子单元并记录偏好，宿主不再绑定设备；新增的
运行时在每次调用时做出放置决策，缓存中没有可用实现时，回到编译期按该单元的中间表示
即时生成目标代码。由此有两条路径：编译产物只含 CPU 实现与可重编译的中间表示；经入口
执行时，GPU 代码在运行期产生。

3. 可靠性。收敛单元边界、编译缓存失效条件、设备容量判定与失败处理，使系统
在没有实现、容量不足或接口不一致时给出明确结果，而不是静默出错。

## 二、成果汇报

一条完整链路已经成立：程序只需给出算子及其放置偏好，即可在运行期完成设备选择与代码生成。
同一进程内，同一算子可在不同设备间重新决策，切回原设备时原有实现仍然有效。

编译产物可独立运行，也可被入口程序读回后补充设备实现，两种用法均已验证。在远端 GPU
主机上，单元、集成与前端三组测试全部通过。

当前只有一个执行器，策略为偏好优先、不可用时回退，负载均衡与算子融合尚未涉及。

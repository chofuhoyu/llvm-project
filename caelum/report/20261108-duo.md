# 运行时算子放置：第一阶段工作报告

> 范围：`caelum/skeleton-dialect`，2026-10-27 至 2026-11-03（`9b3df4a80a6d..78a854b8eab2`）。

## 一、工作进展

本阶段的主线是把算子放置的决策点由编译期移到运行时。围绕这条主线，完成了 GPU 执行路径
的改造、运行时与 driver 的实现，以及实现过程中暴露的一批正确性与边界问题。

### 1. GPU 执行路径改用统一内存

原有的设备调用以 `gpu.alloc` 分配设备内存，并用异步 `gpu.memcpy` 完成数据进出；拷贝所在
的流与 kernel 流之间没有顺序约束，是此前偶发错误输出的来源。本阶段改为主机共享分配
（CUDA 上的 `cuMemAllocManaged`），宿主与 kernel 访问同一块缓冲区，数据搬运改用同步
`memref.copy`。异步 token 与 `gpu.wait` 的编排随之整体移除，只读常量操作数不再回写。
同时修正了目标函数返回 void 时仍按 memref 读取首个结果的问题。

### 2. 运行时放置的实现

运行时由编译期切分、运行时库与 driver 三部分构成，设计记录在 `caelum/doc/runtime.md`。

- **编译期**：`skeleton-outline` 把算子切分为独立单元，单元的 skeleton 形式、放置偏好与
  数据量记录在函数上；`skeleton-lower-dispatch` 把对单元的调用改写为
  `skeleton_rt_resolve` 加一次间接调用。宿主因此不再包含设备信息。
- **运行时库**：实现生成代码所依赖的 ABI——算子声明、按 (op, device) 注册实现、由
  `resolve` 统一做出放置决策并缓存。选择设备后没有可用实现时，`resolve` 回调 provider
  请求编译；设备可用性通过 `dlopen` 查询，不依赖驱动即可启动；决策日志可显式打开。该库
  不链接 LLVM 与 MLIR，以便直接链入产物。
- **driver**：`mlir-skeleton-driver` 是这条路径的入口，负责切分、把宿主降到 LLVM 并 JIT
  执行，以及在运行期按需把单元从自身的 skeleton IR 编译成对应设备的实现。GPU 单元经
  wrapper、`target-lower` 的统一内存桥与 NVVM 管线生成 cubin，再交给运行时加载。
- **产物**：`--emit` 生成独立可执行文件，内含宿主、各算子的 CPU 实现、内嵌于
  `.skeleton.ir` 段的 skeleton IR 与运行时。产物单独运行只执行 CPU 实现；driver 读回该段
  IR 后可为 GPU 重新编译，因此 GPU 代码的唯一来源是运行期重编译。
- 编译期原有的 `preference-partition` 与 `finalize-memref-to-gpu` 在运行时路径覆盖同等
  场景后删除，CPU 与 GPU 的端到端用例统一改由 driver 驱动；`target-lower` 保留为把单个
  单元降为目标代码的工具，不再参与设备选择。

### 3. 正确性与运行约束

实现过程中一并处理了下列问题，它们决定了这一版能否稳定运行。

- **单元边界**：嵌套算子保留在外层单元内，不再单独切分；单元之间的调用与重复的 `op_id`
  被明确拒绝；多结果的限制收窄到偏好 GPU 的单元，偏好 CPU 的单元与零结果单元均可用；
  不带偏好的 linalg 算子留在宿主。
- **接口一致性**：宿主与按需编译的单元之间校验降级后的函数签名；模块属性与 global 随
  单元一并切分；`resolve` 在 provider 回调返回后按 id 重新索引算子表，避免表增长带来的
  引用失效。
- **生命周期与缓存**：每个设备各自保活其 JIT 引擎，同一单元换设备编译不再释放既有实现；
  编译失败按 (unit, device) 记录，避免每次调用重复解析与降级。
- **失败路径**：没有可用实现时打印原因并以非零状态退出，不再出现空指针调用；显存由
  `cuMemGetInfo` 探测，按算子的数据量判断能否容纳，放不下则回退 CPU；`--runtime-lib`
  路径错误在发射前即报出，而非留到链接阶段。
- **产物与构建**：产物内嵌 MLIR bytecode，发射前执行 O2；未开启执行引擎的构建跳过
  driver 相关测试，而不是以失败呈现；C++ 端到端用例在缺少 CIR 时同样跳过。
- **决策日志与 provider 契约**：每次 `resolve` 输出一行，字段为
  probe / free / choose / reason，与实际落点一致；provider 以返回指针为契约，
  `skeleton_rt_register` 只用于启动注册与就地替换；缓存按设备类别记录且不失效，因此
  热插拔、换卡与多卡不在本版范围。
- **数值正确性**：归约的初值由未初始化张量改为元素类型的零常量，消除结果依赖内存残留的
  偶发错误；body-region 形式的 map 与 reduce 均可降级，嵌套的 skeleton 算子则给出明确
  诊断。

## 二、成果汇报

- **链路成立**：一份 skeleton 模块交由 driver 即可完成切分、宿主 JIT 执行与按需的算子
  编译；编译期不再选定设备，设备选择发生在每次调用上。
- **两种运行方式均已验证**：`mlir-skeleton-driver` 直接运行模块；`--emit` 的产物单独运行
  时执行 CPU 实现，driver 读回其内嵌 IR 后可补出 GPU 实现再执行。
- **逐次决策可观测**：同一进程内同一算子可按 GPU、CPU、GPU 的顺序切换，每次调用重新
  决策，切回原设备时先前的实现仍然有效；决策日志与 stats 提供了对应的记录。
- **失败可控**：缺少实现、显存不足、签名不一致均给出诊断并按既定方式退出或回退。
- **验证**：在远端 GPU 主机上完成三轮全量验证，单元、集成与 CIR 三组测试均通过，其中
  包含产物自运行、产物读回重编与设备间切换的用例。
- **规模**：66 个提交，61 个文件，+3589 / −692。

本版的边界是：一个进程一个 executor，策略为放置偏好优先、设备不可用或容量不足时回退
CPU；负载均衡、扁平图上的融合、多 executor 与多机部署均未纳入。`target-lower` 仅作为
lowering 工具保留。
